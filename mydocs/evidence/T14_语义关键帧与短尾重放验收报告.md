# T14 语义关键帧与短尾重放验收报告

## 结论

`DOWNGRADED_REPLAY_ONLY_VERIFIED`

T14 的协议、规范化 codec、兼容性门禁、内容寻址存储、事务恢复、
T09 可选 accelerator 接口和非视觉能力报告均已实现并验证。当前目标
构建没有任何达到门禁的 `RoomEntry`：

- T10 仍明确为 `unity-random-partial-whitelist-v1`；
- 没有房间完成 full/keyframe 各 10 次、目标后 600 tick oracle；
- 当前实机 profile 存在未登记的第三方 Mod；
- 因而没有安全依据实现或启用 PlayerData/SceneData/Hero/RNG 的恢复
  adapter。

按 T14 Spec 的 FAIL/Downgrade 条款，运行时固定为 `ReplayOnly`：
不会捕获、索引或应用关键帧，T09 full replay 是唯一持久化真相源。
这不是 `RoomEntry` PASS，也不宣传短尾重放已经更快。

## 已实现

- `semantic-keyframe-v1` descriptor、严格 canonical codec 和 JSON Schema。
- `keyframe-adapter-manifest-v1`、adapter envelope 和 exact compatibility。
- journal head 以“目标 journal 链中的已验证祖先”判断，而非错误地要求
  等于目标 head。
- 游戏构建、manifest、baseline、adapter manifest、tier、tick 和
  required adapter 的 fail-closed 绑定。
- T09 共享 objects namespace 下的事务化 keyframe store：
  descriptor、独立 index、共享关联、incomplete transaction、corrupt
  index quarantine。
- 删除关联/descriptor 不删除任何 T09 或共享 object；`ReplayOnly` 下
  自动 GC 明确禁用。
- `ReplayOnlyRestoreAccelerator`：规划永远为 `Unavailable`，防御性
  restore 也绝不应用状态。
- `EnableSemanticKeyframes` 设置，默认 `false`。
- session `semantic-keyframe-tier` 事件和 IPC capability/status：
  tier、是否真正注册 accelerator、capture gate、原因码和
  `FullReplay` plan 均可由外部非视觉读取。
- 可重复执行且会恢复设置、存档、Mods、T09 store 和进程状态的
  `scripts/Invoke-T14KeyframeMatrix.ps1`。
