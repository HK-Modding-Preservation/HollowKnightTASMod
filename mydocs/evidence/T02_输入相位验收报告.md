## 5. 选择结论

三个候选均满足语义与恢复门禁。按照 Spec 预先规定的选择顺序，提升 **A** 为正式 `HeroInputAdapter`：

1. 它只依赖公开 `InputManager.OnUpdate` 和自定义 binding source；
2. attach 时准备 sample 0，之后每个已提交 tick 准备下一 logical sample；
3. B 额外依赖生成的 `UpdateInternal` MMHOOK，版本耦合更强；
4. C 依赖 Hero update 节奏，边界离输入系统更远。

B/C 保留为只能通过显式探针参数启用的测试对照，不进入后续正式回放路径。

G0 Input Boundary PASS。T02 证明了 gameplay 动作层的稳定注入、真实输入隔离、边沿消费和异常恢复；它不证明 visual/fixed/input tick 的完整时间模型，也不证明冷启动确定性。下一硬门禁是 T03，最终“已验证重放”仍需 T07。
