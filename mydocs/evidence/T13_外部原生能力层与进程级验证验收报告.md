# T13 外部原生能力层与进程级验证验收报告

## 结论

**T13：PASS / VERIFIED。**

v1 NativeHost 已以签名 Windows x64 sidecar 交付；当前唯一支持的原生能力为
只读 `native.process.observe.v1`。它只能由已认证 Companion 启动，只能观察
当前受信 Hollow Knight PID，并在锁定构建白名单和标准用户 `ProcessQuery`
权限下运行。进程 checkpoint 与 input/clock/capture 原生能力继续明确标记为
`unsupported`，恢复回退 Runtime/T09，没有发布 NativeBridge。

## T07 native off/on 对照

关闭与开启两组各执行 10 次真实冷启动。每个 run 都独立完成：

1. CLI `verification validate`；
2. 回放结果、槽位绑定恢复和五个语义 milestone 导入；
3. 自包含 `runtime/session-events.jsonl` 复制；
4. native expectation 硬校验。

- `NativeObserveExpectation=Disabled`；
- 10/10 Companion 到达 Ready；

`dependencySemanticProjectionPass=true`。跨组比较

## 竞态闭环

早期矩阵只要求 on/off 的 TAS 语义一致，补充 session 审计发现开启组曾有
3/10 只到 started 就随探针退出。最终实现增加逐 run 原生硬门槛：非 Ignore
运行在回放结果后保留固定 settle 窗口，游戏退出后再读取完整事件日志；任何
缺少 verified、attach 数不正确、父进程失败或持久化 raw pages 的运行都会
fail closed。正式 retry3 的独立二次审计重新读取 20 份事件，20/20 通过。

## 边界

T13 证明的是只读进程观察、目标/父进程/构建验证、最小权限、崩溃隔离和
不改变 T07 语义结果。它没有证明完整进程恢复、任意 RAM 写入、全局时间或
I/O 虚拟化。任意时刻/定时且可跨启动选择的 savestate 保证仍来自 T09 的
baseline + replay；最终诸神堂椅子到调谐假骑士路线由 T16 独立验收。
