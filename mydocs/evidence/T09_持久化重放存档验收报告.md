# T09 持久化重放存档验收报告

## 结论

本报告记录的是 T24 原版执行语义门禁建立前的历史验收。T09 的存档事务、
journal、恢复流程和 80 次重复实验当时为 **PASS**，但其中使用了只作用于
TAS 侧的时序改写和坐椅坐标量化；这两项现已退役。因此本报告不能再证明
“与无 Mod 逐帧等价”，T09 在 T24 下为 **REOPENED / NOT ACCEPTED**，必须以
不写 Unity 时钟、不量化目标 hash 的实现重新完成动态验收。

正式证据在：

```text
artifacts/replay-save/final-same-slot2-10/
```

5 个手动存档点和 3 个自动存档点按非时间顺序恢复，每个点在一个独立
游戏进程中连续恢复 10 次。总计 `80/80` 次均满足：

- live canonical Semantic Snapshot v1 原始 SHA-256 与 descriptor 完全一致；
- 恢复后处于已验证暂停点，`nextMovieTick = effectiveMovieTick + 1`；
- input bindings、Hero control 和 Unity time settings 等价恢复；
- 没有把 `v1-float32-decimal-4` 投影相等当成成功条件。

因此该历史构建曾证明：使用者可在安全 committed tick 固化任意请求，
可按 movie tick 定时固化，并可在下次启动选择任一存档点，由 Runtime
自动加载 baseline、重放前缀、严格校验后停在目标点。

## 交付能力

- baseline bundle、连续 journal、canonical movie、目标 snapshot、ledger
  summary 和 content-addressed object store；
- manual、automatic interval、movie checkpoint 三种创建原因；
- requested/effective tick 分离，非安全请求排队到后续安全 tick；
- interval/retention 策略，暂停、加载和 cursor 停止时不重复自动保存；
- 原子 transaction、catalog 重建、corrupt/gap/manifest/schema fail closed；
- 专用 TAS 槽 identical/deny/approved-backup/rollback/commit lease；
- 独立游戏内 overlay：list/create/restore/policy/pin/resume；
- non-blocking restore coordinator、覆盖确认、进度、暂停和继续；
- 可选 accelerator 接口及 unavailable/incompatible/fault/wrong-cursor/
  wrong-hash 全部回退 full replay。

## 已退役的历史确定性方案

T07 已证明自然 Unity visual/fixed 调度在移动路线可能分叉。历史实验曾采用
`unity-capture-delta-equals-fixed-v1`，令 `captureDeltaTime` 等于
`fixedDeltaTime`、关闭 v-sync 并推导 50 FPS；该方案只改 candidate 的运行环境，
违反 T24，现已退役。Runtime 当前必须忽略旧设置
`ReplaySaveDeterministicTimingEnabled`，不得写 `captureDeltaTime`、
`fixedDeltaTime`、`timeScale`、目标帧率或 v-sync。

历史实现还曾把坐椅位置量化后纳入目标 semantic hash。该做法会隐藏真实回放
偏差，现同样退役；恢复成功必须基于未量化的 Float32 canonical snapshot 原始
SHA-256 完全一致。reference/candidate 的时钟、帧相位和 RNG 条件只能由同一个
外部验证环境对称提供。

重复恢复还必须先执行 `ReturnToMainMenu(DontSave)`，等待 `Menu_Title`
稳定，再调用 `LoadGame + ContinueGame`。修复前，同一进程第二次直接
`LoadGame` 会留下旧 Hero 生命周期，基线出现
`hero.actorState expected=grounded actual=airborne`；修复后的 24 次
稳定性矩阵和 80 次正式矩阵均未复现。

## 槽安全

正式 80 次矩阵使用 source slot 2 / dedicated slot 2，baseline bytes
相同，因此恢复路径不写用户槽。真实不同占用槽的拒绝覆盖证据保存在：

```text
artifacts/replay-save/capture-smoke-10/
```

Coordinator 实际进入 `AwaitingOverwriteApproval`，探针拒绝后得到
`Cancelled/Cancelled`，四个槽 hash 不变。approved backup、rollback 和
commit 路径由离线测试与隔离合成槽矩阵验证；本轮没有把任何真实不同用户槽
作为获准覆盖实验。

  持久化重放存档验证，不是通用进程内存快照。
