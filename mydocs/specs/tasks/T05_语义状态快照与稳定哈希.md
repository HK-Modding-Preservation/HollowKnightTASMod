# Task Spec T05: 语义状态快照与稳定哈希

- **Status**: VERIFIED
- **Gate**: G2 Prerequisite
- **Depends On**: T01
- **Produces**: versioned semantic snapshot、canonical bytes、SHA-256、首差异

## 0. Open Questions

- None。v1 先覆盖最小 Hero/scene/gameplay 状态；敌人和任意 FSM 观察由 T11 扩展。

## 1. Requirements

### Goal

把 Hollow Knight 的关键运行时状态转换为稳定、有类型、可排序、可哈希、可 diff 的语义快照，不依赖 Unity instance ID、对象枚举顺序或本地 locale。

### In-Scope

- scene、GameState、Hero transform/velocity/actor state、选定 cState、health/MP。
- typed semantic value、canonical serialization、SHA-256。
- strict exact-bit hash 与人类可读 diff。
- milestone capture；每 tick 全量 capture 不是 v1 强制项。

### Out-of-Scope

- 任意反射对象图。
- 协程、delegate、native Unity object 的序列化/恢复。
- 状态写回或 savestate。
- 未注册敌人/FSM 自动发现。

## 2. Architecture

- Key 使用 versioned semantic path；v1 key 集合固定。
- Value 显式带类型，不从文本猜类型。
- 所有 key 使用 `StringComparer.Ordinal` 排序。
- `float` strict 值按 IEEE 754 single bit pattern 编码；diff 同时显示 round-trip 十进制。
- canonical byte stream 使用固定 big-endian 整数、UTF-8 length prefix、无时间戳。
- Snapshot hash 是 `SHA256(schemaVersion + ordered key/type/value)`。
- 缺失 key 与值为 null 是不同状态；v1 默认不允许 null。

## 3. Detailed Design

### 3.1 v1 Keys


取值失败必须生成 capture error；不得用 `0`、空串或前一 tick 值替代。

### 3.2 Core Interfaces

```csharp
public enum SemanticValueKind : byte
{
    Boolean,
    Int32,
    Int64,
    Float32Bits,
    Utf8String
}

public readonly struct SemanticValue
{
    public SemanticValueKind Kind { get; }
    public byte[] CanonicalBytes { get; }
    public string DisplayValue { get; }
}

public sealed class SemanticSnapshot
{
    public int SchemaVersion { get; }
    public IReadOnlyDictionary<string, SemanticValue> Values { get; }
}

public sealed class SemanticSnapshotBuilder
{
    public void AddBoolean(string key, bool value);
    public void AddInt32(string key, int value);
    public void AddInt64(string key, long value);
    public void AddFloat32(string key, float value);
    public void AddString(string key, string value);
    public SemanticSnapshot Build();
}

public static class SemanticSnapshotHasher
{
    public static string ComputeSha256(SemanticSnapshot snapshot);
}

public static class SemanticSnapshotDiffer
{
    public static SemanticDiff Compare(
        SemanticSnapshot expected,
        SemanticSnapshot actual);
}
```

### 3.3 Runtime Probe Contract

```csharp
public interface ISemanticProbe
{
    string ProbeId { get; }
    void Capture(SemanticSnapshotBuilder builder);
}

public sealed class RuntimeSnapshotCapture
{
    public SnapshotCaptureResult Capture(TickStamp stamp);
}
```

Capture 必须在 T03 选定的稳定 phase 执行。同一 milestone 的 phase 不匹配时，hash 不可比较。

实现反向同步：Core 目标为 `netstandard2.0`，为避免把额外
`System.Memory` 程序集带入 HK Runtime，公开 `CanonicalBytes` 返回防御性复制的
`byte[]`；调用方不能取得内部数组。格式和严格相等语义不变。

## 4. Independent Verification

### Offline PASS

- golden fixture 的 canonical bytes 和 SHA-256 固定。
- 不同字典插入顺序得到相同 bytes/hash。
- `+0/-0`、不同 NaN bit、浮点 1-bit 变化均按 strict 规则区分。
- 修改一个 key 后 diff 恰好报告该 key，包含 expected/actual type、bits、display。
- 缺失、重复、unknown v1 key 被拒绝。

### In-Game PASS

1. 在暂停且 Hero 状态不变的同一 phase 连续 capture 100 次，hash 全相同。
2. 只改变 Hero X 后，首差异至少包含 `hero.position.x`。
3. 只损失生命后，首差异包含 `player.health`。
4. 跨场景后，`scene.name` 变化且 scene epoch 被记录。
5. capture 失败产生显式 error event，不生成伪 hash。

### FAIL

- hash 依赖 instance ID、对象枚举顺序、locale 或 JSON 属性顺序。
- probe 缺失时静默填默认值。
- 为了让 hash 一致而量化/忽略未在 Spec 中声明的状态。

## 6. Compatibility

- v1 key 的类型和语义不可原地改变。
- 新 key 可作为新 schema version 或声明的 optional capability 添加。
- strict hash 是验证依据；未来若增加 tolerant view，只能用于诊断，不能替换 strict hash。
