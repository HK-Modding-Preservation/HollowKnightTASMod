# Task Spec T19: 场景切换期间回放时间轴冻结

- **Status**: READY_FOR_IMPLEMENTATION
- **Gate**: G6 Product Completion
- **Depends On**: T03, T06, T15
- **Produces**: gameplay-aware movie tick gate、跨场景冷启动一致性证据

## 1. Goal

回放穿越异步场景加载时，movie cursor 不得随机器加载速度继续前进。相同 movie
必须在新场景进入可玩状态时恢复同一个后续输入 tick，避免战斗输入因加载耗时
发生数百 tick 漂移。

## 2. Contract

- 以下任一条件成立时，不消费 movie tick：
  - `GameManager` 不存在；
  - `gameState != PLAYING`；
  - `GameManager.IsInSceneTransition=true`；
  - Hero 或 `InputHandler.inputActions` 不可用。
- 诸神堂挑战在 `BeginSceneTransition` 前的原版 `Challenge Start` 预切场阶段也
  不消费 movie tick；该阶段由 Hero 控制/动画语义识别，不依赖像素或固定时长。
- adapter 维持当前 prepared input，但不产生 observation、command 或 cursor 推进。
- 若门禁关闭的同一 raw update 恰好是“无 held/pressed/axis、仅释放确认键”的
  terminal release sample，则先提交该唯一 release boundary，再从中立 sample
  冻结；不得让新 press 或 held input 穿过门禁。
- gameplay 恢复后，在下一个获准的 input boundary 精确继续同一个 movie sample。
- 场景重获控制后的两个 InControl raw update 作为输入边沿 warm-up 被跳过；它们
  不产生 observation 或 movie tick，只用于消除跨场景重复 press/release 边沿，
  并计入 `replaySuspendedRawInputTickCount`。
- 暂停/逐步门禁仍与 gameplay 门禁组合，任一拒绝都不得推进。
- 初始真实椅子流程是可玩的场景内 FSM；不得因
  `HeroController.acceptingInput=false` 而冻结，否则 T17 无法以 movie 输入起身。
- 战斗受击、硬直等游戏内 `no_input` 状态仍消费 tick，除非同时进入上述加载条件。

## 3. Verification

1. 对同一个“诸神堂椅子→雕像→假骑士”movie 连续冷启动至少 3 次。
2. 记录确认难度、transition 开始/结束、`GG_False_Knight` ready 和第一个战斗
   输入对应的 movie tick。
3. 新场景 ready tick 与首个战斗动作 tick 必须逐次一致；raw input/visual tick
   可随加载耗时不同。
4. replay observation 数必须等于 expanded movie ticks + release observation，
   mismatch=0、physical noise=false。
5. 椅子起身和普通非场景切换回放回归通过。

## 4. PASS

- 新场景开始执行的 movie sample 不受加载耗时影响。
- T17 的椅子 FSM 仍能读取起身输入。
- 暂停、停止、异常 cleanup 与 binding restore 保持通过。

## 5. FAIL

- 用固定增加 neutral frames 掩盖加载漂移；
- 以 `acceptingInput` 作为全局 gate 导致椅子或受击期间死锁；
- 加载期间重复产生 movie observation/command；
- 冷启动场景 ready movie tick 仍不一致。

## 6. Rollback

门禁是 Runtime 回放层的组合适配器，不改变 Core movie 语义；失败时移除组合门禁
并保留证据，不修改用户槽或游戏状态。
