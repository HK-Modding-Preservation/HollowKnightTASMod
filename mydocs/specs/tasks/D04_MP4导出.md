# D04：序列导出 MP4

## 当前 v2 Studio 接入（2026-09-26）

本节是当前实现和验收要求，优先于下方旧版 v1 交付记录。用户操作说明为 `docs/MP4-V2.md`。本次新增完整序列及节点区间两种 Studio 导出入口；离线规划与参数检查已通过，新入口的安装版实机验收仍待完成。旧版 Studio 按钮、旧 v1 假骑士视频及旧 v2 接口视频的 PASS 均不能直接继承。

### 两种操作

- **完整序列：** 在受控游戏会话中打开或编辑有效 v2 序列，点击输入编辑器工具栏中的“导出完整 MP4…”，选择已有 FFmpeg 及不存在的 `.mp4` 路径。Studio 同步真实录制输入、保存当前分支，受保护冷重放到输入系统就绪的 Movie 0 边界后采集第一帧输入，到完整 Movie 末尾自动封装。准备初始化不进入视频，不能为方便启动而跳过 Movie 第 1 帧。
- **节点区间：** 在时间线页选节点，分别点击“设为起点”和“设为终点”，检查范围后点击“导出区间 MP4…”。逆序选择自动按祖先关系排序；无祖先关系的不同分支、同一节点或同帧空区间明确拒绝。“清除选择”只清除两个导出端点。

节点区间定义为 `(ancestor.Frame, descendant.Frame]`，即祖先边界之后至后代边界，包含末帧。使用后代节点的完整 v2 Movie 从原始存档冷重放；仅控制何时开始、停止采集，不拼接节点，不截断正文和后代之后的未来草稿。节点 `Frame` 是 Movie 完成帧数，不等于包含加载推进的原生帧数；视频包含起止边界之间实际执行的加载画面，因此输出帧数允许大于端点差。

### 当前约束与状态保护

- 完整输入正文中的所有 run 必须为固定 50 fps；即使其他帧率仅出现在选定终点之后的未来草稿，当前也明确拒绝。沿用 v2 输入格式、展开帧数和源文件大小限制。
- 导出计划校验节点存在性、完整父链、祖先关系、帧边界，以及祖先已执行前缀和环境头一致性。未验证节点可以导出，由正常重放验证到达，不将选择节点本身当作已经成功执行的证明。
- 冷重放使用原始存档的保护副本，检查原始存档哈希及时间线基线；不写角色/Boss 调试状态，不压缩等待，不修改输入、时钟或 RNG。完整导出先完成初始化并停在输入未消耗的 Movie 0 边界。
- 冻结导出输入，锁定冲突的编辑与回放操作。导出结束、失败或取消后恢复原完整编辑草稿及 Undo/Redo；不得用为导出选取的另一分支覆盖用户草稿，也不得截掉未来输入。后续播放重新按编辑草稿建立游戏进度。
- 采集中允许暂停/继续同一操作；暂停等待不增加成片时长。准备冷重放与采集阶段均可取消，取消请求停止并暂停，失败或取消不发布成片。关闭 Studio 先等待本次导出停止。
- 状态区分准备、`Capturing`、`Finalizing`、`Completed`、`Cancelled`、`Failed`。只有编码封装结束且目标文件存在才显示完成；采用操作 ID 跟踪，开始回执丢失时查询已接受的操作，不重复开始。

### 共用接口

`startVideoExport` 新增可选 `endMovieFrame`，表示包含在成片中的最后一个 Movie 帧边界。Broker/MCP 接受正整数且不超过 `MovieProtocolV2.MaximumExpandedFrames`（10000000）；Runtime 还检查大于当前 Movie 起点且不超过已加载序列。v1 收到该字段明确返回 `Unsupported`。省略字段保留从当前暂停点导出至 Movie 末尾的行为。SDK 在原 `cancellationToken` 参数之后增加可选 `endMovieFrame`，兼容既有位置调用。

Studio 自动完成保护冷恢复，再通过与 AI 共用的 `control.playback` 路径开始导出。直接使用 SDK/MCP/CLI 时，调用者负责先恢复所需起点；底层开始命令不会替调用者回档。v2 自动结束采集，不提供手动 `finishVideoExport`。

## 目标与边界

在 Studio 选择已写好的序列及合法起点，重放并生成包含游戏画面和游戏声音的 MP4。人工和 AI 使用同一套开始、状态、取消接口。操作返回独立 operationId，状态包含阶段、已编码帧数、输出路径和失败原因。

参考 [libTAS 的帧捕获机制](https://clementgallet.github.io/libTAS/guides/how/)和[编码选项](https://clementgallet.github.io/libTAS/guides/options/)：画面和音频按模拟时间送入编码器，编码速度可以慢于播放速度。实现采用自己的代码，不复制 libTAS 源码。

正常输入仍走现有原生回放路径。导出模块不写角色状态、不改变 TAS 时钟或游戏速度。暂停等待、外部命令延迟、编码阻塞不增加成片时长。场景切换产生的有效画面和声音需要保留；movie tick 与渲染帧不是同一概念，不可仅按 tick 去重。

## 数据与失败处理

- MP4 使用 H.264 / yuv420p 和 AAC；采集侧固定偶数宽高、RGB24、PCM float 音频。输出采样率和声道与采集侧明确协商。
- 帧率使用约分后的正有理数。经过 N 个输出帧的每声道样本数为 `floor(N × sampleRate × fpsDenominator / fpsNumerator)`；逐帧取累计差，避免独立取整造成漂移。
- 帧率必须与现有回放时钟匹配。第一版无需用户自行改变游戏帧率；时间轴支持分数仅用于精确计算。
- 在现有 CompletedFrameBoundarySignal 边界采集，异常必须在订阅者内处理。Unity 对象只在游戏主线程访问。
- 使用有界传输和流式编码，队列满时背压，不丢帧、不堆积图片文件。分辨率中途变化应明确失败或按预设尺寸缩放，不能静默错解像素。
- 编码器隐藏启动，路径及参数分离。输出先创建独占临时文件，成功关闭、校验后再发布为目标文件；不覆盖已有文件。取消、磁盘满、编码器退出和游戏断连均需终止操作、关闭句柄并报告，不将残片标成成功。
- 音频优先验证 Unity AudioRenderer 离线输出；API 存在不代表实机同步已经成立。必须验证暂停恢复、场景切换与样本计数，不能以墙钟录音替代后宣称同步。
- 旧示范绑定执行环境。修改 Core/Runtime 后保留旧包、旧存档与哈希；新版本按正常路径生成兼容起点和序列，不伪造旧身份或放宽兼容校验。

1. **格式和时间轴。** Core 校验尺寸、帧率和音频格式；整数、分数帧率累计样本数无漂移，非法参数及溢出明确失败。当前 4 项定向单测通过，未安装新版本。

3. **产品入口。** Studio 提供导出与取消；CLI/SDK/MCP 共用操作状态。验证目标文件冲突、取消、编码器失败和资源释放，补充普通用户说明。导出过程与其他回放/回档写操作互斥。
4. **完整交付。** 从有效起点导出假骑士完整序列，确认战斗回放完成。用 ffprobe 检查容器、音视频流、帧数与时长，并检查开头、中段、结尾的画面和声音；导出中插入一次暂停，验证暂停不延长视频。逐阶段提交，最终更新交付范围和安装包。
