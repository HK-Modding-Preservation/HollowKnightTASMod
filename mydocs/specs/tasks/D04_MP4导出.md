# D04：序列导出 MP4

## 目标与边界

在 Studio 选择已写好的序列及合法起点，重放并生成包含游戏画面和游戏声音的 MP4。人工和 AI 使用同一套开始、状态、取消接口。操作返回独立 operationId，状态包含阶段、已编码帧数、输出路径和失败原因。

参考 [libTAS 的帧捕获机制](https://clementgallet.github.io/libTAS/guides/how/)和[编码选项](https://clementgallet.github.io/libTAS/guides/options/)：画面和音频按模拟时间送入编码器，编码速度可以慢于播放速度。实现采用自己的代码，不复制 libTAS 源码。

正常输入仍走现有原生回放路径。导出模块不写角色状态、不改变 TAS 时钟或游戏速度。暂停等待、外部命令延迟、编码阻塞不增加成片时长。场景切换产生的有效画面和声音需要保留；movie tick 与渲染帧不是同一概念，不可仅按 tick 去重。

## 数据与失败处理

- MP4 使用 H.264 / yuv420p 和 AAC；采集侧固定偶数宽高、RGB24、PCM float 音频。输出采样率和声道与采集侧明确协商。
- 帧率使用约分后的正有理数。经过 N 个输出帧的每声道样本数为 `floor(N × sampleRate × fpsDenominator / fpsNumerator)`；逐帧取累计差，避免独立取整造成漂移。
- 帧率必须与现有回放时钟匹配。第一版无需用户自行改变游戏帧率；时间轴支持分数仅用于精确计算。
- 在现有 CompletedFrameBoundarySignal 边界采集，异常必须在订阅者内处理。Unity 对象只在游戏主线程访问。
- 使用有界传输和流式编码，队列满时背压，不丢帧、不堆积图片文件。分辨率中途变化应明确失败或按预设尺寸缩放，不能静默错解像素。
- 编码器隐藏启动，路径及参数分离。输出先创建独占临时文件，成功关闭、校验后再发布为目标文件；不覆盖已有文件。取消、磁盘满、编码器退出和游戏断连均需终止操作、关闭句柄并报告，不将残片标成成功。
- 音频优先验证 Unity AudioRenderer 离线输出；API 存在不代表实机同步已经成立。必须验证暂停恢复、场景切换与样本计数，不能以墙钟录音替代后宣称同步。
- 旧示范绑定执行环境。修改 Core/Runtime 后保留旧包、旧存档与哈希；新版本按正常路径生成兼容起点和序列，不伪造旧身份或放宽兼容校验。

## 分阶段验收

1. **格式和时间轴。** Core 校验尺寸、帧率和音频格式；整数、分数帧率累计样本数无漂移，非法参数及溢出明确失败。当前 4 项定向单测通过，未安装新版本。
2. **采集与编码。** 接入实际渲染和音频，流式生成短 MP4。先验证编码器的尺寸、帧数、声道、采样率及时间戳，再以实机短序列验证声音和动作；合成媒体测试不替代实机证据。
3. **产品入口。** Studio 提供导出与取消；CLI/SDK/MCP 共用操作状态。验证目标文件冲突、取消、编码器失败和资源释放，补充普通用户说明。导出过程与其他回放/回档写操作互斥。
4. **完整交付。** 从有效起点导出假骑士完整序列，确认战斗回放完成。用 ffprobe 检查容器、音视频流、帧数与时长，并检查开头、中段、结尾的画面和声音；导出中插入一次暂停，验证暂停不延长视频。逐阶段提交，最终更新交付范围和安装包。

## 当前证据与下一步

### 实机接入结果

最新结果：`artifacts/d04-live/probe-dsp-60.mp4` 已通过短采集检查。800×450、50 fps、60 帧；H.264 画面和 48 kHz 双声道 AAC 均为 1.2 秒，189630 字节。SHA-256 为 `34864d81829f4954039acfa06d4b6342d73616e9f926bfa806d0ef371bf0f067`。运行 `interactive-817dc52ff0a546f48a2b9d5e44909b89`，操作 `video-ed5ca284f6184db89680d9b28ec1a95a`，从 tick 199 推进到 259。首帧后暂停等待，再查询仍为 1 帧；随后补齐 59 帧，Completed。解码音频均值 -38.8 dB、峰值 -26.1 dB，非静音；首帧图片已检查，画面方向正确。当前画面含 TAS 调试叠加层，产品入口还需提供隐藏选项。

同一进程取消操作 `video-391c7d18d328494c9f5421d2a37b21ce` 到达 Cancelled，tick 保持 259，目标文件和临时目录均未留下。上述结果证明短采集可用，不替代完整序列、跨场景、动作音画同步和 UI 验收。

音频根因已通过本机 UnityPlayer 原生代码确认：Render 内部循环只处理完整 DSP 块，GetSampleCountForCaptureFrame 也按块取整；每帧 960 样本直接传入小于 1024 的缓冲区不会进入渲染循环。AudioBlockReframer 现在预取完整块，把余量留到下一帧，输出长度严格遵循视频时间轴，不丢样本或填充静音。最多预取一个 DSP 块，最后余量不写入成片。3 项定向测试覆盖连续样本顺序、零长度渲染、变长帧及参数错误。

只读复核脚本 `scripts/inspect_unity_audio_renderer.py` 依赖 pefile/capstone，并锁定 UnityPlayer SHA-256 `d97e92a7640b10580b4e60139eacf01828f74baaef53f75e08b9fdd6193fbe5e`。关键 RVA：计数实现 `0xA98420`、Render `0xA98500`、完整块判断 `0xA986B9` 和后续循环 `0xA98B27`。没有修改 UnityPlayer 或游戏时钟。

游戏侧已在 CompletedFrameBoundarySignal 采集画面；音频适配器和异步编码结束、失败清理已接入。startVideoExport 接收 ffmpegPath、outputPath、maximumFrames；finishVideoExport 和 cancelVideoExport 接收 operationId，均要求 control.playback 租约。getState 提供 videoExport.* 状态。导出期间拒绝回档、换序列和调试写入；现阶段仍需调用者从正确起点推进序列，尚无一键导出 UI。

此前短探针失败记录（音频和停滞已由上面的新证据更新）：

- Unity Mono 的托管命名管道初始化失败；改用已有 NativeNamedPipeServer 后，实机开始命令成功。该管道仅允许当前 Windows 用户连接。
- 实际 captureDeltaTime 对应 50 fps。导出读取当前时钟推导帧率，不再假定 60 fps，也不修改时钟。
- 运行 `interactive-90e6187a76d641b1bdb329e426ad2a49`，operationId `video-df0092073a2a4cb3b93e668a5394d2ff`：单步后 Unity 音频计数为 0，预期每声道 960，操作明确失败。
- 诊断运行 `interactive-fc93e1ccb8c44a91b5c8c2f66cbb60b0`，operationId `video-a7e3124360644206bf4079b2ea75469a`：暂时直接调用 Render 提供预期大小的缓冲区；返回成功但最大音频幅度始终为 0。画面送出 24 帧后传输超时，最终 Failed，未发布 MP4。游戏正常完成本次 60 帧步进并停在 tick 151。
- 早期版本曾恢复音频计数不匹配即失败的检查；现已由完整 DSP 块适配替代。编码器加入 zerolatency 后，720p 合成测试及后续实机 60 帧均通过。共用命令的权限与租约另有 1 项测试通过。

下一步是产品入口、完整序列协调与完整回放导出验收。现有命令仍是开发阶段接口。

`VideoExportFormat`、`VideoExportTimeline` 与 `FfmpegVideoEncoder` 已实现。编码器使用独立音画命名管道和各两个缓冲区，超时失败，不写逐帧图片。原始格式已知，因此关闭 FFmpeg 输入探测，避免音频探测与有界生产端互等。取消只终止本次创建的编码器进程。

编码基础的 8 项定向检查通过：4 项时间轴测试；合成 60 帧画面及正弦音频经本机 FFmpeg 编码，ffprobe 确认 H.264、AAC、48 kHz 双声道、音画各一秒；另验证连接前取消、目标已存在、编码期间目标被其他程序创建的文件保护。临时目录均回收。Runtime 的 net472 编译通过，最新 DSP 修复已安装并完成上述实机探针。
