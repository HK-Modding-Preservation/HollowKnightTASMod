- **Status**: VERIFIED

## 0. Open Questions

- None。此任务的目的就是用实验选择方案；Spec 不预设哪一个候选一定成功。

## 1. Requirements

### Goal

证明 Hollow Knight 动作层输入可以在一个稳定相位被采样、隔离和注入，并且 `IsPressed`、`WasPressed`、`WasReleased` 在 Hero 消费前语义正确。

### In-Scope

- Gameplay actions：`left/right/up/down/jump/attack/dash/cast/quickCast/superDash/dreamNail`。
- InControl tick、`InputManager.OnUpdate`、`ModHooks.HeroUpdateHook` 与候选前置 Hook 的顺序探针。
- 自定义 `BindingSource`、真实 binding 暂存/恢复、紧急停止输入。
- 物理输入噪声下的隔离验证。

### Out-of-Scope

- 菜单、暂停、地图、背包和 cutscene 输入。
- 完整 movie 回放。
- 修改 `UnityEngine.Input` 或 OS 键盘输入。
- 在实验通过前确定永久 Hook 实现。

## 2. Architecture

已知源码事实：

- `InputManager.UpdateInternal` 在 action set 更新完成后触发 `OnUpdate`。
- `HeroController.Update` 在原始输入消费前触发 `HeroUpdateHook`。
- `PlayerAction` 合并所有 regular bindings；只追加 TAS source 会允许真实输入混入。

候选策略必须至少比较：

1. **A：公开 `InputManager.OnUpdate` 后预装下一 logical sample**；attach 时预装 sample 0，下一 InControl tick 由 action set 正常提交。
2. **B：`On.InControl.InputManager.UpdateInternal` 前置 Hook**；在调用 `orig` 前装载当前 logical sample，同 tick 由 action set 提交。
3. **C：`HeroUpdateHook` 中预装下一 logical sample**；不直接写 `PlayerAction` 私有/内部状态，若 Hero 消费前边沿映射不稳定则判失败。

选择标准依次为：语义正确、侵入性低、恢复可靠、版本适配面小。

探针只在显式命令行参数存在时启用，普通启动零行为变化：

```text
--hktas-input-probe=A|B|C
--hktas-input-probe-run=<run-id>
--hktas-input-probe-case=normal|physical-noise|emergency-stop|scene-change|adapter-exception
--hktas-input-probe-slot=<1..4>
--hktas-input-probe-exit
```

探针等待 `Menu_Title` 稳定后只读加载指定测试存档；fixture 期间默认暂时令 Hero 不接受 gameplay 输入，恢复时还原原值，避免修改测试存档。`scene-change` 使用 `ReturnToMainMenu(DontSave)`。

## 3. Detailed Design

### 3.1 Core Types

```csharp
[Flags]
public enum TasAction : ushort
{
    None = 0,
    Left = 1 << 0,
    Right = 1 << 1,
    Up = 1 << 2,
    Down = 1 << 3,
    Jump = 1 << 4,
    Attack = 1 << 5,
    Dash = 1 << 6,
    Cast = 1 << 7,
    QuickCast = 1 << 8,
    SuperDash = 1 << 9,
    DreamNail = 1 << 10
}

public readonly struct InputSample
{
    public ulong InputTick { get; }
    public TasAction Held { get; }
    public TasAction Pressed { get; }
    public TasAction Released { get; }
    public short AxisX { get; }
    public short AxisY { get; }
}
```

`AxisX/AxisY` 范围固定为 `[-10000, 10000]`。digital left/right/up/down 与 axis 同时出现时由上游静态校验拒绝。

### 3.2 Runtime Interfaces

```csharp
public interface IHeroInputAdapter : IDisposable
{
    string CandidateId { get; }
    void Attach(HeroActions actions);
    void Prepare(InputSample sample);
    CapturedHeroInput Observe(ulong inputTick);
    BindingRestoreReport DetachAndRestore();
}

public sealed class BindingLease : IDisposable
{
    public static BindingLease Acquire(
        HeroActions actions,
        IReadOnlyDictionary<TasAction, BindingSource> tasBindings);
    public BindingRestoreReport Restore();
}
```

`BindingLease` 只接管 gameplay action。紧急停止 action 必须保留独立物理绑定，且不进入 movie。

`BindingLease.Acquire` 对每个 gameplay `PlayerAction.UnfilteredBindings` 保存对象引用与顺序，然后 `ClearBindings()` 并只加入对应 TAS source；恢复时再次 `ClearBindings()`，按原顺序 `AddBinding` 原对象，并做引用/顺序等价比较。不得依赖 `RemoveBinding` 的延迟 orphan 清理。

紧急停止由独立 `PlayerActionSet` 的 `F8` 物理 binding 提供，永不进入 `BindingLease`。

### 3.3 Fixed Edge Fixture

按 InControl tick 执行：

| 区间 | 目标输入 |
|---|---|
| 0-9 | 全部释放 |
| 10-29 | `right` hold |
| 30 | `right+jump`，jump 首次 press |
| 31-38 | `right+jump` hold |
| 39 | `right`，jump release |
| 40 | `right+attack`，attack press |
| 41 | `right`，attack release |
| 42 | `right+dash`，dash press |
| 43 | `right`，dash release |
| 44-59 | 全部释放 |

每次实验同时记录：

- InControl tick、visual/fixed counters。
- 物理 source 值、自定义 source 值。
- 每个 action 的 `Value/IsPressed/WasPressed/WasReleased`。
- HeroUpdateHook 进入时状态。
- Hero 位置、速度、actor/cState 的最小结果。

Runtime 原始证据写到当前 T01 session 下的 `input-phase/<runId>/`；矩阵脚本在进程退出后复制到仓库忽略的 `artifacts/input-phase/<sessionId>/`。每个 run 必须生成 `phase-events.jsonl`、`binding-before.json`、`binding-after.json`、机器可读 `result.json` 和 `verdict.md`。

## 4. Independent Verification

### Matrix

- 候选 A/B/C 各执行至少 10 次独立进程启动。
- 每个候选固定 10 次分布：5 次 normal、2 次 physical-noise、1 次 emergency-stop、1 次 scene-change、1 次 adapter-exception。
- `physical-noise` 期间外部 harness 实际按住相反方向和 attack；`emergency-stop` 实际发送 F8。
- 每批矩阵在只含 Modding API + HollowKnightTAS 的隔离 Mods profile 中执行；脚本以显式原子目录交换建立 profile，并在 `finally` 恢复普通 profile。

### PASS

- 固定 fixture 的每个 press/release 在 Hero 消费前恰好出现一次。
- 10 次运行的 `inputTick -> edge` 映射完全相同。
- 回放期间物理 gameplay 输入不改变采样结果。
- 紧急停止始终可用。
- 正常停止、场景切换、异常三条路径均恢复与 attach 前等价的 binding 集合及顺序。
- 不通过反射写入未知私有内存来维持成功。

### FAIL / No-Go

- 没有任何候选能稳定产生边沿语义。
- 真实输入无法可靠隔离，或恢复后控制失效。
- 相位依赖偶然 MonoBehaviour script order 且无法锁定/验证。

T02 FAIL 时，T06/T07 不得开始；项目降级为只读 Inspector/诊断工具，或另立原生输入层研究。
