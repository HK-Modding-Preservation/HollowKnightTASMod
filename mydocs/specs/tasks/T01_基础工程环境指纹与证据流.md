## 1. Requirements

### Goal

把“只有文档的仓库”变成可重复构建、自动安装、启动后能留下可审计环境证据的最小工程。此任务不实现输入注入、回放、步进或 UI。

### In-Scope

- `netstandard2.0` Core、`net472` Runtime、`net8.0` CLI/Tests 的解决方案骨架。
- 机器路径隔离、HK DLL 引用校验、Debug 构建后自动安装/打包。
- Mod 生命周期、全局设置、session 目录、环境 manifest。
- Modding API 日志和 JSONL 结构化事件。
- 验证模式的环境预检；发现未声明 Mod 时拒绝验证模式。

### Out-of-Scope

- 输入、tick、movie、状态哈希、IPC、Companion/Studio、NativeHost。
- 自动移动/禁用用户现有 Mods。
- 把绝对游戏路径、存档内容或个人信息写进仓库。

## 2. Architecture

- Runtime 只依赖 Core；Core 禁止引用 Unity、Modding、PlayMaker 或 InControl。
- 每次游戏进程只创建一个 `sessionId`，格式为 UTC 时间 + 128-bit 随机 ID。
- session 输出根目录为 `Application.persistentDataPath/HollowKnightTAS/sessions/<sessionId>/`。
- 主日志仍写 `ModLog.txt`；机器可读事件另写 `events.jsonl`。
- JSONL writer 使用单生产者 Unity 主线程队列 + 后台文件 writer；退出时有有界 flush，绝不在主线程无限等待。
- manifest 使用 canonical UTF-8 序列化后计算 SHA-256；绝对路径不进入 canonical 内容。

`TasRuntimeHost.Start()` 只能执行一次；`Stop(reason)` 幂等。它在 `FinishedLoadingModsHook` 后创建 manifest/session，在 `ApplicationQuitHook` 中先写 `session-stop`，再按设置做有界 flush 和 hook 注销。

`LoadedModsWithVersions` 是存档元数据容器，Modding API v77 的启动加载器不会填充它，因此不得用作启动环境指纹。Runtime 在 `FinishedLoadingModsHook` 中通过
`ModHooks.GetAllMods(onlyEnabled: true, allowLoadError: false)` 一次性捕获名称/版本快照；verification preflight 与 manifest 必须消费同一个快照。

### 3.2 Manifest Fields

必填：

- 游戏版本、`ModHooks.ModVersion`。
- `Assembly-CSharp.dll`、`PlayMaker.dll`、`MMHOOK_Assembly-CSharp.dll`、Runtime/Core DLL 的 SHA-256。
- `ModHooks.GetAllMods(onlyEnabled: true, allowLoadError: false)` 返回的当前 Mod 名称/版本快照，按 ordinal key 排序。
- TAS 设置 canonical hash。
- baseline ID/hash；未选择 baseline 时写显式 `none`。
- OS、进程位数、locale、图形质量、分辨率、目标帧率、音频启用状态。
- verification requested/allowed 与按 ordinal 排序的 unexpected Mod 名称。

禁止：

- 用户名、Steam ID、完整磁盘路径、原始存档内容。

### 3.3 Build Contract

- `HollowKnightTAS.Runtime` 目标为 `net472`。
- Debug build 自动复制 Runtime/Core DLL 和 PDB 到 `$(HKModsDir)\HollowKnightTAS`。
- 同一 build 生成 `HollowKnightTAS.zip` 和 `SHA256.txt`。
- 缺少本地 props 或 DLL 时，MSBuild 错误必须指出缺失项和修复入口。
- Runtime 初期最小引用：`Assembly-CSharp.dll`、`UnityEngine.dll`、`UnityEngine.CoreModule.dll`；只有后续任务需要时再加入 PlayMaker/MMHOOK/Physics2D。

### 3.4 CLI Contract

```text
HollowKnightTAS.Cli manifest validate <manifest-path>
```

- 验证必填字段、类型、canonical UTF-8 字节和 SHA-256。
- 若同目录存在 `manifest.sha256`，必须与计算结果一致。
- 成功输出 `VALID <lowercase-sha256>` 并返回 `0`。
- 参数错误返回 `2`；文件/JSON/schema/canonical/hash 错误返回 `3`，stderr 给出单行原因。
- `Program.Run(args, stdout, stderr)` 是可独立测试的命令边界；`Main` 只负责绑定标准流，所有预期校验错误不得越过该边界导致未处理异常。

## 4. Independent Verification

### Offline

```powershell
dotnet build .\HollowKnightTAS.sln -c Debug
dotnet test .\tests\HollowKnightTAS.Core.Tests\HollowKnightTAS.Core.Tests.csproj -c Debug
dotnet run --project .\src\HollowKnightTAS.Cli -- manifest validate <manifest-path>
```

### In-Game

1. 启动仅含 Modding API + HollowKnightTAS 的隔离 profile。
2. 到主菜单后退出。
3. 核对 `ModLog.txt` 中恰好一次 `session-start` 与一次 `session-stop`。
4. 核对 session 目录含 `manifest.json`、`events.jsonl`。
5. CLI 验证 canonical hash。
6. 在普通多 Mod profile 启动验证模式，确认它拒绝开始但不影响游戏正常退出。

### PASS

- Debug build 0 error；安装目录和 zip/hash 均存在。
- Core tests 全通过。
- 同一个 manifest 反复 canonicalize 得到相同字节与 SHA-256。
- JSONL 的 sequence 严格单调、每行独立可解析、退出无截断行。
- 验证模式能识别未声明 Mod，失败路径有结构化事件。

### FAIL / Downgrade

- 构建依赖需要提交真实机器路径。
- Runtime 启动或退出导致游戏卡死。
- manifest 包含敏感路径或字段顺序导致 hash 漂移。
- 普通 profile 被自动修改。

## 6. Rollback

### 2026-09-07 日志容量补充

- `JsonLinesEventSink` 默认单文件上限 64 MiB，可通过构造参数指定正数上限。
- 按 UTF-8 字节和换行计费，只保留完整事件行；触顶后停止追加并累计丢弃数，flush 仍可完成。
- 首次触顶生成相邻 `.incomplete` 标记；带此标记的事件流不能作为完整验收证据。
- 本批不删除历史日志，不限制 movie、用户存档或正式逐帧 trace；跨 session 总容量管理仍待实现。
- 用小容量定向测试验证边界和截断标记，不启动游戏矩阵。

- 删除新建 solution/source/test 文件即可回到纯文档仓库。
- Runtime 的 `Dispose`/退出路径必须取消所有订阅并关闭 writer。
- 不删除用户 session 证据；清理证据属于单独、显式操作。
