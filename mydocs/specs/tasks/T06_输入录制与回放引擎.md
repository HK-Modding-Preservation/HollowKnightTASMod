## 1. Requirements

### Goal

在 T02 选定的稳定输入边界上持续记录 HeroActions，写成 T04 movie；加载编辑后的 movie 后，隔离真实 gameplay 输入并按 T03 tick 语义回放。为了支持 T09 的“任意时刻存档”，TAS profile 从 baseline 建立后必须始终维护连续 shadow journal，而不是等用户显式点击录制才开始。

### In-Scope

- `Idle/Recording/Replaying/Stopping/Faulted` 模式。
- 从新游戏或存档加载 baseline 起持续运行的 shadow journal。
- 数字/量化轴输入、RLE、marker/checkpoint/assert 事件调度。
- manifest/baseline/movie ID 校验。
- 正常停止、场景变化、死亡、异常时恢复 binding。
- 独立紧急停止。

### Out-of-Scope

- 菜单、cutscene 和存档 UI 自动化。
- 冷启动 10-run 判定；属于 T07。
- 暂停/步进/快进；属于 T08/T09。
- 隐藏状态强写与 RNG 控制。

## 2. Architecture

- Core state machine 不引用 Unity。
- Runtime adapter 只负责在 T02 phase 调用 Core 并把 `InputSample` 应用到 HeroActions。
- Record 读取的是 action state，不读取 `UnityEngine.Input`。
- `AfterSavegameLoadHook`/新游戏 ready boundary 建立 baseline 后立即启动 shadow journal；显式 Recording 只是把同一 journal 标记为用户 movie，不另起一条可能缺前缀的输入流。
- journal 使用有界内存段并持续原子刷入 session 存储；任何 gap 都使之后的 T09 savepoint 不可创建。
- Replay 进入前获取 `BindingLease`；退出时先释放所有 TAS action，再恢复物理 bindings。
- Movie cursor 与 raw InControl tick 分离：raw tick 可从任意绝对值开始；从 baseline 建立后的每个符合条件的 `InControlCommitted` tick 恰好让 cursor 推进一次。visual/fixed tick 只用于关联账本与诊断，不消费 movie sample。
- assert 在声明的 milestone phase 执行；失败立即进入 `Faulted` 并释放输入。

## 3. Detailed Design

```csharp
public enum PlaybackMode : byte
{
    Idle,
    Recording,
    Replaying,
    Stopping,
    Faulted
}

public sealed class MovieCursor
{
    public long MovieTick { get; }
    public int CommandIndex { get; }
    public int OffsetWithinFrameRun { get; }
    public InputSample CurrentInput { get; }
    public bool MoveNext();
}

public sealed class PlaybackStateMachine
{
    public PlaybackMode Mode { get; }
    public PlaybackStartResult StartRecording(RecordingContext context);
    public PlaybackStartResult StartReplay(
        MovieDocument movie,
        PlaybackContext context);
    public PlaybackTickResult Advance(TickStamp stamp);
    public PlaybackStopResult Stop(PlaybackStopReason reason);
}
```

```csharp
public sealed class RuntimePlaybackController : IDisposable
{
    public PlaybackMode Mode { get; }
    public StartResult StartRecording(string outputPath);
    public StartResult StartReplay(MovieDocument movie);
    public StopResult EmergencyStop();
}
```

```csharp
public sealed class ReplayJournal
{
    public string BaselineId { get; }
    public long FirstMovieTick { get; }
    public long LastCommittedMovieTick { get; }
    public bool HasGap { get; }
    public JournalAppendResult Append(InputSample sample, TickStamp stamp);
    public JournalSlice CommitThrough(long movieTick);
}
```

### State Rules

- 只有 `Idle` 可进入 Recording/Replaying。
- `Faulted` 不可直接重启，必须完成 cleanup 并显式 reset。
- scene epoch 变化、Hero 不存在、manifest 变化、assert 失败均触发 fail closed。
- movie 结束自动输出全释放 sample 至少一个边界，再恢复 binding。
- Recording 只在受支持的 gameplay lifecycle、目标 scene、Hero 已存在且 runtime mode 允许时推进 movie cursor；不能把 `HeroController.acceptingInput` 作为唯一或必要条件。该字段仍写入状态/证据，菜单、加载、无 Hero 或不支持的生命周期生成 suspension event。
- shadow journal 在受支持的 gameplay lifecycle 中持续记录，即使 UI 处于 `Idle`；若不能建立或续接已知 baseline，savestate capability 必须显示 unavailable。

## 4. Independent Verification

### Offline

- 由输入样本序列编码 RLE，再展开，逐 tick 完全相等。
- mode transition table 全覆盖；非法 transition 被拒绝。
- movie cursor 在 marker/checkpoint/assert 周围无 off-by-one。
- 任意异常路径最终达到 `Idle` 或可诊断 `Faulted`，不会保留 lease。

### In-Game

1. 在锁定 baseline 上录制固定短路线。
2. 只编辑一个等待区间的 RLE 长度，静态校验通过。
3. 同一进程内回放原版与编辑版各 5 次。
4. 回放时故意施加相反物理输入。
5. 在正常结束、手动停止、scene change、受控异常四种路径检查 binding。
6. 不进入显式 Recording，直接游玩一段后请求 T09 checkpoint，确认 journal 已覆盖 baseline 到目标 tick。

### PASS

- 录制的 press/hold/release 与 T02 观测一致。
- RLE round-trip 无信息损失。
- 原始 movie 在同一 baseline 的 5 次回放都命中预定终点 milestone。
- 编辑后的时间变化只影响预期区间。
- 物理 gameplay 输入不泄漏。
- 四条停止路径的 binding restore report 全 PASS，停止后手动控制正常。
- shadow journal 在 baseline 后无 gap；未显式录制的第 6 项仍能导出完整前缀。

### FAIL

- movie tick 与输入边沿出现不稳定 ±1 漂移。
- 失败后 Hero 输入被锁死或真实输入仍混入。
- scene/baseline 不匹配仍继续回放。

## 6. Rollback

- 停止顺序固定为：停止 cursor → 输出全释放 → detach TAS bindings → 恢复真实 bindings → flush evidence。
- cleanup 失败时禁止再次 replay，并提示用户重启游戏。
