# Task Spec T17: 椅子起身状态一致性

- **Status**: READY_FOR_IMPLEMENTATION
- **Gate**: G6 Product Completion
- **Depends On**: T06, T11, T15
- **Produces**: 原版椅子退出路径、动画语义 watch、坐姿冷启动回放回归证据

## 1. Goal

从真实长椅坐姿开始回放时，不得由回放器强制恢复 Hero 控制并绕过原版
椅子 FSM。首个 movie 输入应由原版椅子逻辑消费，随后 Hero 的控制、物理、
动画和 `PlayerData.atBench` 必须共同进入正常离椅状态。

## 2. Contract

- 非椅子场景保持 T06 既有控制租约行为。
- 当 `PlayerData.atBench=true` 且 `HeroController.acceptingInput=false` 时，
  回放器不得调用 `RegainControl()`、不得直接修改 `PlayerData.atBench`、不得
  强制播放动画。
- 回放输入绑定仍在同一 input tick 生效，由游戏原版椅子 FSM 决定何时起身。
- 原版逻辑恢复输入后，回放器把该状态视为游戏产生的新控制基线；结束回放时
  不得再次把 Hero 冻结回坐姿控制状态。
- 场景切换后的既有控制重获逻辑保持可用。

## 3. Non-visual Observability

Inspector/Automation 必须提供稳定 typed watch：

- `hero.control.acceptingInput`
- `hero.control.relinquished`
- `hero.animation.controlEnabled`
- `hero.animation.clip`
- `hero.animation.frame`

这些字段用于证明动画控制已交回 Hero 且实际 clip 不再是坐姿；图片、OCR 或
人工观察只可作为补充，不能作为 PASS 判据。

## 4. Independent Verification

1. 用锁定的诸神堂椅子 fixture 冷启动，movie 首段仅包含正常方向输入。
2. 起点必须记录 `atBench=true`、`acceptingInput=false`。
3. 离椅后必须记录：
   - `atBench=false`；
   - `acceptingInput=true`、`relinquished=false`；
   - `animation.controlEnabled=true`；
   - 移动期间 clip 为正常移动/空中动画，而非椅子坐姿 clip；
   - Hero 位置变化来自 movie 输入。
4. replay mismatch 为 0、无物理输入噪声，结束后 binding/control cleanup 通过。
5. 再跑一个非椅子 fixture，证明旧回放路径无回归。

## 5. PASS

- 不写 `PlayerData`、不强跳 FSM、不强制动画即可完成真实离椅。
- 结构化 watch 同时证明控制、动画、位置和长椅标志一致。
- T06/Core 回归和实机冷启动用例通过。

## 6. FAIL

- Hero 移动时 clip 仍为坐姿；
- 仅调用 `StartAnimationControl()` 掩盖状态不一致；
- 直接清除 `PlayerData.atBench` 或强制 FSM event；
- 回放结束后 Hero 被错误冻结，或非椅子回放退化。

## 7. Rollback

改动只限控制租约分支与只读 watch。失败时恢复 T06 控制路径；不得污染用户
存档或将视觉补丁作为替代方案。
