## 1. Requirements

### Goal

在不混淆 Unity visual/fixed/input 边界的前提下暂停 gameplay simulation，并按请求推进一个明确边界，同时记录实际产生的所有账本事件。

- `Running/Pausing/Paused/Stepping/Restoring/Faulted` 状态机。
- `Time.timeScale` gate 候选策略。
- movie cursor gate；暂停期间不消费新 movie command。
- 原始 time settings 捕获与全路径恢复。
- overlay/日志明确展示 visual/fixed/input 实际增量。

### Out-of-Scope

- 冻结整个进程、线程、音频设备、unscaled UI。
- 未经证据声称与 libTAS 帧步进等价。
- 检查点和快进。
- 修改 `fixedDeltaTime` 作为默认方案。

## 2. Architecture

- `Time.timeScale=0` 只负责关闭 scaled time/physics，不能单独构成产品暂停门禁。
- Companion 产品路径必须在完整 `LateUpdate` 结束后阻塞 Unity 主线程；暂停墙钟期间
  不得产生额外 gameplay `Update/LateUpdate`、输入边沿、动画、VFX 或 FSM 工作。
- 后台 IPC reader 可以继续等待 Human/AI 的 step/resume 命令；命令只能在封闭
  boundary pump 中应用，然后开放下一条完整原版更新管线。
- 每个 step 请求包含目标边界类型；v1 只允许 T03 已证明可观测的类型。
- Step result 必须返回实际 `visualDelta/fixedDelta/inputDelta/movieDelta`，UI 不隐藏差异。
- 任一 scene change、游戏 pause menu、focus loss 或异常都先恢复原始 time settings。

## 3. Detailed Design

```csharp
public enum SimulationControlMode : byte
{
    Running,
    Pausing,
    Paused,
    Stepping,
    Restoring,
    Faulted
}

public enum StepBoundary : byte
{
    MovieTick,
    VisualUpdate
}

public readonly struct StepRequest
{
    public StepBoundary Boundary { get; }
    public int Count { get; }
}

public sealed class StepResult
{
    public int MovieTickDelta { get; }
    public long VisualTickDelta { get; }
    public long FixedTickDelta { get; }
    public ulong InputTickDelta { get; }
    public IReadOnlyList<TickLedgerRecord> Ledger { get; }
}

public sealed class RuntimePauseController : IDisposable
{
    public SimulationControlMode Mode { get; }
    public ControlResult Pause();
    public ControlResult Step(StepRequest request);
    public bool TryTakeCompletedStep(out StepResult? result);
    public ControlResult Resume();
}
```

`Step` 对外部调用方是非阻塞请求；Runtime 在后续安全 `LateUpdateEnd` 完成
`StepResult`。处于 Companion 暂停时，Unity 主线程必须阻塞在已完成的 frame
boundary 等待后台 IPC，而不是继续空跑零 `timeScale` frame。独立诊断 probe 可保留
旧非阻塞策略，但不得作为 Human/AI TAS 产品路径。

`TimeSettingsLease` 至少保存/恢复：`Time.timeScale`、`Time.fixedDeltaTime`、`Application.targetFrameRate` 和由本任务主动改变的设置。没有改变的设置不得重写。

## 4. Independent Verification

### Pause Test

- 进入静止与运动中两种状态分别暂停 5 秒墙钟时间。
- 记录 raw counters、movie cursor、Hero semantic hash。
- 预期：movie cursor 不变；Hero gameplay hash 不变；任何仍前进的 raw counter 被如实报告。

### Step Test

- 从同一 baseline 执行 100 次单步。
- 每步保存 StepResult。
- 对比正常速度运行相同 100 movie ticks 的 milestone hash。

### Restore Test

- 正常 resume、scene change、focus loss、受控异常、mod shutdown 五条路径。
- before/after time settings exact-bit 比较。

### PASS

- 暂停期间 movie cursor 与 gameplay hash 稳定。
- 每次请求恰好消费声明数量的 movie tick。
- 所有实际 visual/fixed/input 增量完整可见。
- 不只比较终点：每个 gameplay tick 的输入、Hero 动画/物理/FSM/VFX 和资源必须
  满足 T24 无 Mod 差分门禁。
- 100-step 终点 hash 与正常速度基线一致。
- 五条路径都恢复原始 time settings。

### Naming Verdict

- 只有当每步的目标 phase 和实际增量在所有运行中严格一致，才允许显示 `Tick Step`。
- 若只保证 movie cursor 一步、而 visual/fixed 增量可变，则 UI 必须显示 `Visual Step` 或 `Controlled Step`。
- 若终点 hash 不一致，该策略只能作为诊断实验，不进入产品。

## 6. Rollback

- `Dispose`、`finally`、scene event、application quit 均调用 idempotent restore。
- restore 失败时记录 exact before/actual values，并提示用户重启游戏；不得继续 step。
