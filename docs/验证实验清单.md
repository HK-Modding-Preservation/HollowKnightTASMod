# Phase 0 / Phase 1 / 外部能力验证实验清单

本清单用于把 README 中的工程推断变成可审计证据。它不是 Mod 代码设计；任何实验结论都要写明**游戏构建、Modding API、Mod manifest、设置、操作系统、硬件、次数和原始日志位置**。

任务的精确文件、接口、验收命令、失败降级和依赖关系已拆到 [`mydocs/specs/tasks/README.md`](../mydocs/specs/tasks/README.md)。本页继续作为跨任务的实验记录模板和总体验收清单。

## 统一实验前提

- 锁定一个游戏构建和对应 Modding API；记录可执行文件/关键 DLL hash。
- 从仅含 Modding API + TAS Mod 的干净 profile 开始；其他 Mod 一律列入 manifest。
- 一次实验只改变一个变量：输入注入相位、帧率/负载、快进策略或附加 Mod。
- 每次回放输出 machine-readable ledger：`visualTick`、`fixedTickCount`、`tft`、输入、场景事件、RNG 计数、milestone hash。
- hash 使用稳定语义键，不使用跨运行的 instance ID；原始日志不可只保留截图。`[建议]`
- 外部进程实验额外记录 Companion/NativeHost/Bridge 的签名 manifest、SHA-256、协议版本、PID/创建时间、capability ID 与权限声明。

## Phase 0：是否值得做 MVP

| 编号 | 实验 | 最小操作 | 必填数据 | Go 条件 | No-Go / 降级条件 |
|---|---|---|---|---|---|
| P0-1 | 输入消费点 | 在每个候选动作层/Hook 相位录制同一短序列 | action 边沿、Hero 状态、tick 账本 | 能得到稳定且可解释的消费相位 | 相同 movie 的输入边沿或行为无规律漂移。 |
| P0-2 | 时间轴模型 | 60/低帧/高负载下跑同一场景 | visual tick、fixed count、T-FT | 帧与物理步关系可记录、差异可解释 | 无法定义可重复 tick 语义。 |
| P0-3 | 最小哈希 | 只 hash Hero/场景/少量状态，冷启动重复至少 10 次 | 每 milestone hash、首个差异 | 目标短路线 10 次一致 | 相同环境持续分叉且无法定位。 |
| P0-4 | RNG 诊断 | 记录目标房间随机调用计数/可见结果 | 调用计数、状态/结果、场景 | 重复回放可收敛，或差异可归因 | 未知调用频繁导致不可复现。 |
| P0-5 | 加载与重生 | 覆盖进/出场景、死亡、重生、菜单/读档 | scene event、hash、tick 账本 | 加载后可回到预期 milestone | 事件顺序或 hash 不可收敛。 |

Phase 0 只有在 **P0-1、P0-2、P0-3** 都通过时才进入 Phase 1。P0-4/P0-5 若失败，必须缩小支持场景或先做诊断工具，不能掩盖为“可验证”。

## Phase 1：MVP 验收

| 编号 | 实验 | 验收标准 |
|---|---|---|
| P1-1 | movie 解析与静态校验 | 非法命令、未知版本、manifest 不匹配在启动前拒绝，并给出明确错误。 |
| P1-2 | 输入录制—编辑—回放 | 同一短路线从录制、RLE 编辑到重放的里程碑 hash 一致。 |
| P1-3 | 近似单步 | 每次单步产生的实际 visual/fixed 账本可见；UI 不把它误称为通用“帧步进”。 |
| P1-4 | 持久化重放存档 | 在静止、运动、场景切换请求期分别手动保存，并按 movie tick 自动保存；重启后任选至少 3 个存档执行“baseline 加载—前缀重放—hash 对照”各 10 次。 |
| P1-5 | 快进回归 | 正常速度与每种快进策略在同一路线的指定 hash 一致；不一致则策略禁用。 |
| P1-6 | desync 报告 | 首个差异能导出输入、T-FT、fixed count、场景、RNG、语义状态差分。 |
| P1-7 | 独立安装 | 至少一份独立安装/机器的匹配 manifest 回放；结果单独标记“已验证环境”。 |
| P1-8 | 语义关键帧加速 | 至少 3 个白名单房间、5 类目标点分别执行 T09 full replay 与 T14 keyframe + tail 各 10 次；目标 hash、cursor、RNG 和后续 600 tick oracle 一致。损坏、缺 adapter、不兼容和 unsafe capture 均自动干净回退 T09。 |

T06 的 16 进程矩阵通过。T07 又以静止 grounded/idle 的锁定 oracle 完成

范围的 P0-3/P1-2/P1-6 已达到 `LOCAL_VERIFIED`。移动路线曾因 visual/fixed
调度出现 111/113 fixed tick 分叉，未被隐藏纠偏；加载、重生、RNG 和
P1-7 独立安装仍分别待后续任务/实验。

P1-3 已由 T08 通过：100 次请求均消费 1 个 movie tick，但实际增量为
79 次 `visual/fixed/input=1/0/1` 和 21 次 `1/1/1`，所以能力名称固定为
`Controlled Step`。静止/运动暂停与五类恢复路径通过，9 份完整 ledger
均有效；不宣称通用 fixed-tick 或 libTAS 等价步进。

P1-4 已由 T09 通过：5 个手动点与 3 个 interval=120/retention=3 自动点
按非时间顺序各恢复 10 次，`80/80` 次 canonical semantic SHA-256 原始值
完全一致，cursor 均为目标 + 1。暂停期间 movie tick/auto 数量稳定；
真实不同占用槽拒绝覆盖和同 bytes 槽零写入均通过。证据位于
`artifacts/replay-save/final-same-slot2-10/`，支持范围仍为锁定本机

P0-4 与 RNG 部分的 P1-6 已由 T10 通过：5 个独立 MATCH 进程的受控

## Phase 2：Companion 与外部/原生能力验收

| 编号 | 实验 | 验收标准 |
|---|---|---|
| P2-1 | Companion 自动启动 | 干净随包安装可由 Mod 自动启动并握手；关闭设置时零进程创建；已有兼容实例不重复启动。 |
| P2-2 | Bundle 篡改/路径逃逸 | 缺失、改 hash、错误签名/RID/协议、绝对路径、`..`、reparse point 均在执行前拒绝，Runtime/T09 保持可用。 |
| P2-3 | 生命周期与 crash loop | 超时、立即退出、连续崩溃、Companion 中断和游戏退出矩阵通过；无启动风暴、误杀进程、输入锁或 `timeScale` 遗留。 |
| P2-4 | IPC 与确定性 | 100 次重连、60 分钟 soak、非法 framing/backpressure 通过；Companion 自动启动开/关各 10 次 T07 oracle hash 一致。 |
| P2-5 | NativeHost 目标与权限 | 仅标准用户权限、仅当前认证 HK PID/创建时间/构建可 attach；任意 PID/地址/DLL/命令和 movie 触发全部拒绝。 |
| P2-6 | Native capability 单项门禁 | 每项 capability 单独开/关做至少 10 次 T07 对照，独立给出 `verified`、`experimental` 或 `unsupported`；不得相互外推。 |
| P2-7 | T13 同进程进程级 checkpoint 实验 | 安全 tick 恢复后即时 hash 与后续 600 tick oracle 一致；加载/死亡/存档写入期拒绝；失败自动回退 T09，且不宣称跨启动或等同 T14 语义关键帧。 |

P2-1 至 P2-4 是 T12 的必过项。P2-5 是 T13 基础设施必过项；P2-6/P2-7 按 capability 判定，失败只禁用对应能力，不撤销 Runtime/T09 已验证能力。

当前实施记录：P2-1 至 P2-4 已由 T12 正式矩阵通过。P2-5 与 P2-6 中的
`native.process.observe.v1` 已由 T13 正式矩阵通过：off/on 各 10 次逐 run
原生门槛与语义对照、on 合计 1,000 次 attach；input/clock/capture 与 P2-7
process checkpoint 仍为 `unsupported` 并回退 Runtime/T09。证据位于
`artifacts/native/t13-final-formal-retry3-20260731T123924565Z/`。

## Phase 3：外部自动化与 AI 接口验收

| 编号 | 实验 | 验收标准 |
|---|---|---|
| P3-1 | 状态资源完整性 | SDK/CLI/MCP 读取同一 session 的 manifest、tick/phase/freshness、semantic hash、watch、RNG、replay-save 和 desync，canonical 结果一致且无敏感路径/token。 |
| P3-2 | 认证与控制租约 | 未认证/错 session/manifest/nonce 全拒绝；两客户端只能有一个 write lease；TTL、断线、用户撤销和 Runtime 重启均回收。 |
| P3-3 | 控制 parity | pause/resume/step/run-until/record/replay/save/restore 通过游戏内、SDK/CLI、MCP 各执行 10 次，ledger/cursor/hash/cleanup 一致。 |
| P3-4 | AI movie 分支闭环 | scripted agent 连续 10 次完成 observe→proposal→validate→run→diff；非法 patch 执行前拒绝，未显式接受时原 movie hash 不变。 |
| P3-5 | backpressure/soak | 10,000 次 read、100 次 reconnect、60 分钟订阅通过；慢客户端不阻塞 Unity 主线程，gap/降采样显式记录。 |
| P3-6 | 安全矩阵 | 任意路径、shell、进程、DLL、URL、反射、地址、原始存档、native enable 均无 capability 或被 schema 拒绝；credential 不进入 stdout/log/audit。 |

P3 全部通过后才能把 T15 标为 `ApprovedControl` 可用；任一控制项失败先降为 `ReadOnly`，认证或数据边界失败则 `Disabled`。

## 风险处理原则

- **同输入分叉**：优先缩小支持 profile 和观测范围；不要立即加入隐藏的状态强写入。
- **RNG 失步**：先做调用计数、来源定位与日志，再考虑逐构建 hook 白名单。
- **重放存档不收敛**：将该存档标为不可验证并报告日志缺口或首差异；不要把反射全对象图当作默认解法，也不要覆盖用户原始槽位。
- **语义关键帧不兼容/失步**：丢弃 accelerator candidate，清理部分应用状态，从干净 baseline 自动回退 T09 并保留失败证据；不得修改 expected hash 或恢复到附近状态。
- **其他 Mod 改变结果**：manifest 不匹配时禁止验证模式；兼容性另立实验矩阵。
- **快进改变 hash**：禁用该策略或仅允许非验证预览模式。
- **Companion 缺失/篡改/崩溃**：不执行、不循环拉起、不阻止 Mod；保留游戏内 Runtime/T09，并输出结构化状态。
- **Native capability 失配**：按 capability fail closed；不得切换到模糊进程名、宽松 hash 或管理员模式。
- **即时 checkpoint 不可恢复**：标记 `unsupported` 并回退 T09；PSS/minidump 只能作为诊断证据，不能作为恢复成功。
- **外部/AI 控制异常**：立即撤销 write lease、拒绝新控制、由 T12 恢复输入/时间并保留审计；不得让 AI 获得隐藏命令或把自然语言直接执行。

这些实验直接落实了 README 的事实/推断/建议边界：证据不足时，结论只能保持“实验性”或“不支持”。
