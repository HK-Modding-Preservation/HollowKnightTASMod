# 实施可行性与任务地图

## 当前项目是什么

当前仓库已从研究阶段进入**按 Spec 顺序实施**：

- 已完成：T01-T13 的适用门禁；其中 T09 完成任意/定时持久化重放存档与 80-run 严格恢复，T12 完成 Companion/IPC 与 60 分钟耐久，T13 完成签名只读 NativeHost 和 native-off/on 各 10 次逐 run 原生/语义矩阵；T14 已安全降级并验证为 ReplayOnly；T15 Automation/AI 非视觉接口已验证。
- 当前：T16 自编 TAS 端到端最终验收。
- 尚未完成：从诸神堂椅子真实冷启动到击败调谐假骑士的自编 movie 与连续 5 次计分运行。

因此锁定本机环境和静止 oracle 已达到 `LOCAL_VERIFIED`；跨安装仍为
`NOT_RUN`，完整 TAS 工具和任意路线仍未完成。

## 结论

项目按以下定义可以立项：

> 面向 Hollow Knight `1.5.78.11833` 的动作语义级输入录制/重放、任意/定时持久化重放存档、tick 账本、状态检查、同步验证和 TAS 编辑工具。

产品架构确定为四个协作层：

1. **Runtime Mod**：HK 输入、tick、状态语义、游戏内最小控制、确定性证据、T09 重放存档和可选 T14 语义关键帧加速。
2. **Companion/Studio**：随 Mod 发布并可由 Mod 自动启动，承担编辑器、本地 IPC、存档目录、日志和外部能力编排。
3. **Automation/AgentBridge**：T15 向调试客户端和 AI 提供稳定语义状态、typed control、SDK/CLI 与本地 stdio MCP；默认只读，控制需用户批准和短期租约。
4. **NativeHost**：默认关闭的 Windows x64 用户态能力层，只承载经过 T13 单独验证的原生能力。

以下目标不在**纯 Mod**可行范围内，但不再永久排除；它们必须进入 T13 外部/原生能力门禁：

- 与 libTAS 等价的进程级即时内存 savestate；
- 通用 RAM 搜索/写入；
- 系统时间、线程、文件、网络、Steam 和音频设备状态的完整虚拟化。

其中任意/定时、跨启动选择存档仍由 T09 的 baseline + journal + cursor + hash 保证。T14 可在已验证房间入口保存语义关键帧并缩短恢复尾段；T13 外部即时快照即使通过，也只是更底层的可选同进程能力。

## 为什么现在可以开始原型

- 本机目标游戏和 Modding API 版本明确，构建依赖完整。
- HK 原生 `HeroActions`、InControl `BindingSource`、`PlayerAction` 与 ModHooks 提供了动作层观测/注入候选面。
- Hero、scene、Rigidbody2D、PlayerData 和 FSM 均可提供语义级观测。
- 文本 movie、canonical hash、ledger diff 和 Companion/Studio 大部分逻辑可以在不启动游戏的纯 .NET 层测试。
- CelesteTAS 官方实现提供了“游戏 Mod + 独立 Studio + 共享协议 + 随游戏启动 Studio”的实际先例；它不证明 HK 的确定性，但足以支持 T12 的外部工具路线。
- Celeste/Speedrun Tool 的 savestate 依赖游戏专用对象图深拷贝、显式 RNG/输入/静态状态恢复和不安全状态拒绝；这支持 T14 的 adapter + eligibility 结构，但不支持在 HK 通用深拷贝全部 Unity 对象。
- T12 将提供受信 Runtime/Companion 管道，T15 再在 Companion 一侧增加外部 automation broker；Runtime 不直接暴露端口或对象图。

仍需实验而不能预先承诺：

- T05 已证明最小状态 schema 可保持稳定 canonical 语义；
- T07 已证明锁定静止 oracle 可在独立进程冷启动下重复收敛；
- T10 已证明两个目标构建白名单 hook 不改变受控 semantic trace，同时
  观察到 room ambient Unity RNG 仍有白名单外消费；
- 快进、移动/加载路线与更完整 RNG 覆盖仍需后续实验。

## Go / No-Go 规则

- T02 失败：停止“可验证回放”路线；只保留 Inspector/诊断工具，或另立原生输入层研究。
- T03 失败：不使用“逐 tick/帧精确”表述，降级为普通动作回放。
- T07 失败：先缩小 profile、路线和状态范围，不用隐藏状态强写掩盖失步。
- T09 的任意/定时存档若不能重建到 T07 hash：该存档标记损坏/不可验证，不允许静默跳过差异。
- T10 无法覆盖未知随机源：manifest 必须保留 `coverage=partial`；
  未知构建 fail closed，不能复用旧 token/hook。
- T14 任一关键帧/adapter/hash 不兼容：禁用该加速路径并自动回退 T09；不得修改 expected hash 或恢复到附近状态。
- T12 启动路径、参数或可执行文件若可被 movie/IPC 任意控制：立即 No-Go；外部进程缺失/损坏时必须降级而不是阻止 Runtime 加载。
- T13 任一 capability 若无法证明目标 PID/构建、最小权限、T07 hash 一致和崩溃恢复：该 capability 标记 `unsupported`，不得因 NativeHost 已存在而默认启用。
- T15 若出现越权控制、两个写客户端并发、任意路径/反射/进程入口、缺少审计或外部控制改变 T07 hash：控制面 No-Go，降为 `ReadOnly`；认证/数据边界失败则 `Disabled`。
- T16 计分运行若依赖截图/OCR/像素、人工中途输入、状态 mutation、强制场景或 teleport，或者 5 次冷运行未全部完成调谐假骑士击杀：项目最终门禁不通过。
